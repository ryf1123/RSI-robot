# 文献地图：用 agent 迭代机器人，这条线是怎么走过来的（查到 2026-08）

按「agent 改的是什么」分六条轴。每条只写：它改什么、它的反馈是什么、以及它**没有**控制住什么。

## 轴 1：agent 改奖励函数

- **Eureka**（Ma et al., ICLR 2024，[arXiv:2310.12931](https://arxiv.org/abs/2310.12931)）——这条线的起点。
  环境源码进 prompt，GPT-4 写奖励代码，RL 训完把**奖励反思**（各项的数值统计 + 任务指标）喂回去，
  演化式迭代。29 个任务里 83% 超过人类专家。
  它自己做了两组消融：**去掉演化**（一次性采 32 个样本）和**去掉奖励反思**（只给快照数值），
  两组都变差 —— 所以论文的结论是「演化不可或缺」。
  **它没有控制住的**：奖励项的**语义**。GPT-4 一上来就知道 humanoid 要往前跑、要站直。
  「先验」和「迭代」在它的设置里没有被分开，因为自由形式的代码空间里
  「随机提议」根本没法定义，也就没有下限可比。本项目就是把空间做成离散可枚举的，
  好让「随机」这条下限存在。
- **Text2Reward**（[text-to-reward.github.io](https://text-to-reward.github.io/)）——从自然语言目标生成稠密奖励程序，强调可读、可人工迭代。
- **DrEureka**——把同一套东西用在域随机化参数上；**Eurekaverse**——用在环境课程上，环境和策略共演化。
- **CurricuLLM**（[arXiv:2409.18382](https://arxiv.org/abs/2409.18382), ICRA 2025）——改的是**任务课程**，不是奖励本身。
- **Text2Touch**（[arXiv:2509.07445](https://arxiv.org/html/2509.07445v1)）——LLM 设计的奖励做到了真机灵巧操作，是这条线少见的实机结果。
- **Reward Design Agent**（[arXiv:2606.01672](https://arxiv.org/html/2606.01672v1)）——2026 年的后续，明确指出
  **Eureka 的反思信号是纯数值且粗糙的，失败模式不同但分数相近时无法区分，
  于是无法诊断「为什么坏」和「怎么修」**，解法是加视觉评估。
  这一条直接支持本项目第四环的问题：**反馈的粒度到底值多少。**

## 轴 2：agent 改任务 / 场景 / 数据

- **RoboGen**（[arXiv:2311.01455](https://arxiv.org/pdf/2311.01455)）、**GenSim**、**Gen2Sim**——用基础模型自动造任务、场景、监督信号。
- **Voyager**——终身学习 agent：自动课程 + 可执行技能库 + 自我验证，Minecraft。

## 轴 3：agent 改代码 / 算法本身

- **FunSearch**、**AlphaEvolve**、**The AI Scientist**、**MLE-STAR**——agent 直接编辑源码去刷指标。
- **ADAS / 自演化 agent 综述**（[arXiv:2509.02547](https://arxiv.org/pdf/2509.02547)）——把「自演化 agentic 系统」统一成一个框架。

## 轴 4：反思与自我改进的机制

Reflexion / Self-Refine / CRITIC / Chain-of-Verification —— 「生成—反馈—再生成」的通用形式。
本项目关心的是其中**反馈那一路到底带了多少信息**。

## 轴 5：**这条线的对照组问题**（本项目最相关的一条）

- **《When Is an LLM Worth It for Hyperparameter Optimization?》**（[arXiv:2606.21641](https://arxiv.org/html/2606.21641v1)）——
  表格数据 HPO 上做预算匹配对照，关键控制是**把 LLM 的那个「默认配置热启动」也发给经典方法**。
  结论极硬：
  - 第 1 次评估 LLM 就到 88.7%，**但那是默认配置，不是 LLM 提的**；
  - 12 次评估里 LLM 自己的提议只多加 **+0.40 个百分点**；测试集上是 **−0.01 pp（p=0.92）**；
  - 经典方法一旦拿到同样的热启动，**5 次评估内领先就消失**，12 次时反超 0.37 pp。
  一句话：**表观上的样本效率全部来自那个默认配置，不来自模型。**

  这正是本项目预注册的第 1 条预测在另一个领域的版本。差别在于：
  他们的「默认配置」是一个人给的常数，而机器人奖励设计里，
  **LLM 的先验本身就是那个默认配置**——它不需要人给，它自己就知道 hopper 要往前走。
  所以在机器人这一侧，问题要重新问一遍，而且要能把「先验」单独关掉。**关掉的办法就是把项名匿名化。**

- **LLM as a Complementary Optimizer**（[arXiv:2405.19732](https://arxiv.org/pdf/2405.19732)）——把 LLM 当成梯度下降的补充而不是替代。

## 轴 6：评测方法学

GENEA Challenge 系列（在姊妹项目 seamless-interaction 里详细写过）给的教训在这里同样成立：
**指标必须同时有上限和下限。**本项目的 decoy mass 天然有：下限 0.0，随机水平 5/17 = 0.294。

## 这张地图上，本项目占哪个格子

| | 已有工作 | 本项目 |
|-|-|-|
| 搜索空间 | 自由形式代码（随机提议无法定义） | **离散可枚举**（随机提议 = 严格下限） |
| 消融的对象 | 演化 on/off、反思 on/off | **语义 on/off（匿名化）× 反馈 on/off** 的 2×2 |
| 主指标 | 任务成功率 | 任务指标 **+ decoy mass（上下限已知）** |
| 埋点 | 无 | **5 个已知诱饵项**（3 有害 + 2 无关） |
| 内层噪声 | 一般 1–5 个种子，很少报 | **先量噪声底，再读曲线**（见第一环） |
